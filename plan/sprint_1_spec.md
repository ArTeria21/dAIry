# Sprint 1 — Backend карты: рабочая кластеризация, устойчивый лейблер, честная подпись кэша

## Цель

`GET /api/map` возвращает осмысленные кластеры (а не «всё — шум одного цвета»), не падает при сбоях
OpenRouter и корректно инвалидирует кэш при пере-обогащении заметок. Только backend
(`web/backend/`); фронтенд этого спринта не касается (он — спринт 2).

## Контекст (см. fable_report.md §1.1)

Текущее состояние `web/backend/dairy_web/analysis.py`:

- `HdbscanClusterer.cluster()` запускает HDBSCAN **на сырых 1024-мерных эмбеддингах** с евклидовой
  метрикой и `min_cluster_size = max(2, min(8, len(vectors)))` (= 8 при N ≥ 8). В таком пространстве
  HDBSCAN помечает почти все точки шумом (`-1`).
- `_clusters_by_id()` молча выбрасывает метку `-1`: точки остаются в payload с `cluster_id = -1`,
  но кластеров нет и никакой диагностики не всплывает.
- `UmapProjector.project()` — UMAP(n_components=2, random_state=42), метрика евклидова по умолчанию.
- `OpenRouterClusterLabeler.label_clusters()` — по одному блокирующему LLM-вызову на кластер, без
  try/except и таймаута: сбой OpenRouter роняет `/api/map` (на cache-miss) и `/api/rebuild` целиком.
- `note_set_signature()` хеширует только id заметок → пере-обогащение заметки (изменившийся
  эмбеддинг/темы при том же id) не инвалидирует снапшот.
- В боте есть таблица `note_entry_state (id, content_hash)` — хеш текста каждой заметки,
  обновляется watchdog-ом при любом изменении текста. Layer3 её сейчас не читает.

## Scope

### In scope
1. Пайплайн кластеризации: снижение размерности **до** HDBSCAN, косинусная метрика, вменяемые параметры.
2. Диагностика шума: `n_noise` в снапшоте, кэше и ответе `/api/map`.
3. Отказоустойчивый лейблер: таймаут + fallback на статические лейблы.
4. Подпись кэша с учётом содержимого заметок (через `note_entry_state.content_hash`).
5. Обновление/добавление тестов на всё перечисленное.

### Out of scope
- Любые изменения фронтенда (спринт 2).
- BERTopic (осознанно отложен — см. fable_report.md P0-3; вернёмся при редизайне topics-over-time).
- e5-префиксы эмбеддингов (`passage:`/`query:`): требуют пере-эмбеддинга всего корпуса на стороне
  бота; смешивать префиксованные и непрефиксованные эмбеддинги нельзя. Не трогать.
- Доприсоединение шума к кластерам (`approximate_predict`) — сначала смотрим на честную долю шума.
- Изменения схемы БД бота (запрещено глобальным инвариантом G1/G2).

## Ключевые архитектурные решения

**АР-1. Два независимых UMAP-прохода.** Кластеризация и отображение — разные задачи:
- **Для кластеризации**: новый компонент `UmapReducer` → `umap.UMAP(n_components=10, n_neighbors=15,
  min_dist=0.0, metric="cosine", random_state=42)`. Выход подаётся в HDBSCAN.
- **Для отображения**: существующий `UmapProjector`, к параметрам добавить `metric="cosine"`
  (остальное как было: `n_components=2, random_state=42`).

**АР-2. Параметры HDBSCAN** (на редуцированном 10-мерном пространстве):
`min_cluster_size=6`, `min_samples=3`, `cluster_selection_method="eom"`. Константы модуля с
комментарием «пересмотреть при N > ~1000». Формулу `max(2, min(8, len(vectors)))` удалить.

**АР-3. DI-швы сохранить.** `AnalysisService` получает reducer/clusterer/projector/labeler через
конструктор (как сейчас); в тестах — фейки, реальные umap/hdbscan в юнит-тестах не запускаются.
Ленивые импорты `umap`/`hdbscan` внутри методов — сохранить.

**АР-4. Малые выборки.** Если `N < 15`: кластеризацию не запускать вообще; все точки
`cluster_id = -1`, `clusters = []`, `n_noise = N`. (UMAP-проекция для отображения при `2 <= N < 15`
выполняется как обычно; при N < 2 — существующий empty-snapshot путь.) Порог — константа
`MIN_NOTES_FOR_CLUSTERING = 15`.

**АР-5. Лейблер с страховкой.** `OpenRouterClusterLabeler`:
- таймаут на HTTP-вызов (параметр `timeout` клиента OpenAI SDK, 20 с);
- каждый вызов в try/except; при любой ошибке — fallback-лейбл этого кластера по логике
  `StaticClusterLabeler` (top-темы через " / ");
- ошибки логируются (`logging`, уровень warning), но никогда не превращаются в 5xx.

**АР-6. Подпись кэша.** `note_set_signature` принимает дополнительно словарь
`{note_id: content_hash}`:
```
signature = f"count={N};max={max_id};state={sha256('|'.join(f'{id}:{hash}' for sorted ids))}"
```
- `EnrichmentReadStore` получает метод `note_content_hashes()` → читает `note_entry_state` (read-only,
  как остальные запросы).
- Если таблица отсутствует или пуста (старые базы) — деградация к текущему поведению (хеш только id),
  без ошибок.
- Формат строки подписи изменится для всех → первый запрос после деплоя вызовет один полный
  recompute. Это ожидаемо, зафиксировать в worklog.

**АР-7. `n_noise` — сквозной.** Поле добавляется в снапшот, в таблицу `metadata` кэша
(`analysis_cache.sqlite3` — его схему менять можно, это наш кэш), в ответы `/api/map` и
`/api/rebuild`. Миграция кэша не нужна: при отсутствии колонки/несовпадении схемы допустимо
пересоздать таблицы кэша (кэш пересобираемый по определению).

## Инварианты спринта

- S1-1. База бота открывается только `mode=ro`; чтение `note_entry_state` — тем же read-only путём.
- S1-2. HDBSCAN никогда не запускается на пространстве размерности > 50. (Тест-страховка на фейках:
  clusterer получает векторы той размерности, что вернул reducer.)
- S1-3. `/api/map` и `/api/rebuild` не возвращают 5xx из-за сбоя LLM-лейблера.
- S1-4. Точки с `cluster_id = -1` присутствуют в `points` (не выбрасываются), но не образуют кластера.
- S1-5. Сумма `len(points) == n_noise + Σ cluster.size`.
- S1-6. Никаких recompute на обычных GET при совпадающей подписи (существующие тесты кэша остаются зелёными).

## Edge cases и ожидаемое поведение

| # | Кейс | Ожидаемое поведение |
|---|---|---|
| E1 | 0 заметок | Существующий empty snapshot: `points=[]`, `clusters=[]`, `n_noise=0` |
| E2 | 1 заметка (UMAP не может проецировать) | Не падать: точка в центре `(0.5, 0.5)` либо empty-путь — выбрать и зафиксировать в тесте; `cluster_id=-1`, `n_noise=1` |
| E3 | N=14 (ниже порога) | Проекция есть, кластеров нет, все `-1`, `n_noise=14` |
| E4 | HDBSCAN пометил всё шумом | `clusters=[]`, `n_noise=N`, ответ 200 |
| E5 | OpenRouter недоступен/таймаут | Кластеры со статическими лейблами, 200, warning в логе |
| E6 | LLM вернул пустую строку/мусор | Существующий `_clean_cluster_label` + fallback "Cluster {id}" сохраняются |
| E7 | `note_entry_state` отсутствует в БД | Подпись по id (деградация), без исключений |
| E8 | Заметка есть в `notes`, но нет в `note_entry_state` | В строку подписи входит с пустым хешем (`id:`) |
| E9 | content_hash изменился при том же наборе id | Подпись меняется → recompute (ключевой новый тест) |
| E10 | Кэш от старой версии схемы (нет колонки n_noise) | Таблицы кэша пересоздаются, recompute, 200 |
| E11 | Эмбеддинги разной размерности в одной базе | Существующий явный `ValueError` сохраняется (не маскировать) |

## Критерии приёмки

- **AC-1.** Юнит-тест с синтетикой: 3 группы по 30 векторов (1024-dim), разделимые по косинусу
  (например, случайные вектора вокруг трёх ортогональных центров) → **реальный** пайплайн
  UmapReducer+HDBSCAN (это один интеграционный тест, где библиотеки запускаются по-настоящему;
  пометить `@pytest.mark.slow`) находит ≥ 2 кластеров и `n_noise / N < 0.5`.
- **AC-2.** `GET /api/map` содержит `n_noise` (int ≥ 0), инвариант S1-5 проверяется тестом.
- **AC-3.** При выброшенном из фейкового лейблера исключении `/api/rebuild` → 200, лейблы кластеров
  непустые (fallback), в points/clusters всё согласовано.
- **AC-4.** Изменение `content_hash` одной заметки (тот же набор id) → `note_set_signature` меняется
  → следующий `GET /api/map` делает recompute (счётчики фейков растут).
- **AC-5.** Повторный `GET /api/map` без изменений → recompute не выполняется (существующее
  поведение, тесты зелёные).
- **AC-6.** При `N < MIN_NOTES_FOR_CLUSTERING` фейковый clusterer не вызывается вовсе.
- **AC-7.** Все тесты `web/backend` зелёные; ничего не пишется в файл БД бота (существующий
  read-only тест зелёный).
