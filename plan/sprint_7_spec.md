# Sprint 7 — Карта: читаемый кластерный слой + удаление заметок + хвост P2 из code review

## Цель

Три блока работ:
1. Карта перестаёт выглядеть «паутиной»: прямоугольные халлы удаляются, подписи кластеров встают в

## Ключевые архитектурные решения

**АР-1. Сцепленные проекции (backend).** В `AnalysisService._recompute`
(`web/backend/dairy_web/analysis.py`): при `N >= MIN_NOTES_FOR_CLUSTERING` сначала
`reduced = self.reducer.reduce(vectors)`, затем **и** кластеризация, **и** 2D-проекция работают от
`reduced`: `labels = self.clusterer.cluster(reduced)`,
`coordinates = self._project_coordinates(notes, reduced)`. При `N < MIN_NOTES_FOR_CLUSTERING`
поведение как сейчас (детерминированная раскладка при N < 5, иначе проекция сырых векторов).
Смена кода не меняет подпись кэша → после деплоя нужен один `POST /api/rebuild` — зафиксировать
в worklog и в ответе пользователю.

**АР-2. Кластерный слой без халлов (frontend).** `ClusterLayer` переписывается:
- **Никаких прямоугольников/халлов.** Только текстовые подписи.
- Позиция подписи — **медиана** x и y видимых точек кластера (медиана, не среднее — устойчивее к
  выбросам). Кластер без видимых точек подписи не получает (это закрывает и «фантомный халл»).
- Стиль: mono uppercase, Schematic Blue, как сейчас; лёгкая подложка cream (`paint-order` /
  text-shadow цветом канвы), чтобы подпись читалась поверх точек.
- **Коллизии:** жадный алгоритм — кластеры сортируются по size по убыванию; подпись рисуется, если
  её оценочный bbox (ширина ≈ `label.length * 7px` при текущем кегле, высота ≈ 14px, в экранных
  координатах с учётом текущего transform) не пересекает уже размещённые; иначе подпись скрывается.
- Скрытая подпись появляется, когда её кластер выделен (клик по чипу легенды) — подпись выделенного
  кластера рисуется **всегда** и поверх остальных; при активном выделении подписи прочих кластеров
  приглушаются (slate).
- Подписи пересчитываются при изменении zoom/pan (bbox в экранных координатах зависит от scale).

**АР-3. Слой подписей — только в CLUSTER-режиме.** В MOOD/TOPIC не рендерится вовсе.

**АР-4. Палитра TOPIC-режима.** Без выбранной темы: все точки — Slate `#858483` (средне-серый,
однородный «фон готовности», не чёрный). С выбранной темой: совпадающие — Ink Black `#181818`,
остальные — Mortar `#dedede` (светлее дефолта — иерархия «выбранное темнее, остальное растворяется»).
Активный чип легенды — orange, как сейчас. Обновить `topicMutedColor`-использования аккуратно:
в MOOD/CLUSTER режимах приглушение остаётся текущим (`#858483`); для TOPIC-режима ввести отдельную
константу `topicDimmedColor = "#dedede"` в `palettes.ts` (правка токенов — G13 не затрагивается,
это viz-палитра).

**АР-5. P2-хвост, решения по пунктам:**
- **P2-2**: `normalizeTimeline` (`services/insights.ts`) коэрсит каждый bucket:
  `total: Number(bucket.total) || 0`, `counts` — объект с числовыми значениями (нечисловые → 0).
- **P2-3**: в `MapView.loadNote` — generation guard (ref-счётчик, как уже сделано в
  `JournalView.loadDay`): применять результат только если вызов всё ещё актуален; выбор другой
  точки инвалидирует предыдущий запрос.
- **P2-4**: `ui/Legend.tsx` — фиксированная высота зоны легенды (две строки чипов,
  `overflow-y: auto` внутри), одинаковая во всех режимах; убрать `min-h`.
- **P2-5**: удалить `topicHighlightColor` из `palettes.ts` (потребителей нет).
- **P2-7**: per-week tooltip stream-графика: один обработчик `onPointerMove` на svg вычисляет
  индекс ближайшего bucket'а из x-координаты (`round(x / step)`), состояние
  `hoveredWeekIndex` + слой под курсором → tooltip-текст
  `TOPIC · WEEK OF <weekStart> · <count> NOTES (<share>%)` в маленьком абсолютном div
  (cream, hairline, 2px, mono). `<title>`-подход удалить. `onPointerLeave` прячет.
- **P2-8**: stream-svg получает `overflow-visible` (как у heatmap); правило месячного тика
  унифицировать с heatmap: подпись у недели, **содержащей 1-е число месяца** (сейчас stream
  подписывает по месяцу понедельника недели → расходится с heatmap на неделях стыка месяцев).
  Общую функцию «неделя содержит 1-е число» вынести в разделяемый модуль `seasons/monthLabels.ts`
  и использовать в обоих компонентах.
- **P2-9**: README — заменить оба упоминания `openai/text-embedding-3-small` на
  `intfloat/multilingual-e5-large` с примечанием про 1024-мерные embedding'и.

**АР-6. Удаление заметок.** Симметрично редактированию (спринт 4): layer3 не пишет в vault,
всё удаление — через внутренний API бота.

*Бот* (`edit_api.py` + `note_editing.py`):
- Новый эндпоинт `POST /internal/notes/delete`, body
  `{note_id, note_path, expected_sha256}`, тот же `X-Edit-Token`. Статусы: 200
  `{"deleted": true}` / 401 / 404 / 409 / 422 — семантика как у replace-text.
- Чистая функция `delete_note_block(content, note_id, note_path, expected_sha256)`: находит блок
  той же `parse_daily_entries`-логикой, сверяет канонический sha (optimistic lock — удаляем только
  то, что пользователь видел), удаляет блок **целиком** (заголовок + тело + managed
  enrichment-строки), схлопывая границу до одной пустой строки между соседними блоками.
  Frontmatter, H1, навигация и соседние блоки — байт-в-байт.
- Выполнение — внутри `journal_lock`: `prepare_for_write` → read/delete/write →
  `commit_and_push` с сообщением `web delete: {note_id}`; `GitPushError` — локальный успех
  с warning (как в edit).
- **Файл дня никогда не удаляется**, даже если удалён последний блок (v1): остаётся frontmatter +
  H1 + навигация. Удаление файлов и починка соседних ссылок — backlog.

*Чистка БД бота (обязательная часть):* удалённый блок оставляет в `notes`/`note_entry_state`
осиротевшие строки, и заметка продолжит висеть на карте. Хуже: при удалении базового id
(`…T10:00`) бывший дубль `…T10:00#2` при повторном парсинге становится базовым — id съезжают.
Агент должен **исследовать текущее поведение watchdog-reconcile** (`enrichment.py`,
`background_reconciler.py`, `enrichment_db.py`): если reconcile уже вычищает строки по id,
исчезнувшим из файла, — покрыть это тестом; если нет — реализовать чистку в reconcile-проходе
(строки `notes`/`note_entry_state`, чей `note_path` — этот файл, а id отсутствует среди
распарсенных). Чистка в reconcile (а не в delete-хендлере) закрывает заодно и ручные удаления
в Obsidian. Писать в БД бота можно только коду бота (G1 не нарушается).

*Layer3* (`app.py`): `DELETE /api/notes/{note_id}`, body `{expected_sha256}`, auth как у всех;
`note_path` — из БД по id (не от клиента); прокси в бот; маппинг статусов как у PUT
(200/404/409/422/502 «editing disabled»).

*Frontend* (`NoteEditor.tsx` или соседний компонент): в не-editing состоянии рядом с EDIT —
кнопка `DELETE` (ghost, slate). Клик → инлайн-подтверждение: текст `DELETE THIS NOTE?` + кнопки
`CONFIRM DELETE` (dark filled) / `CANCEL`. Подтверждение → `DELETE /api/notes/{id}` с
`expected_sha256` текущей версии. После успеха:
- в Reader — refetch дня (заметка исчезает из ленты);
- в NotePanel — сброс выбранной точки, локальное скрытие точки из payload карты
  (авторитетное исчезновение придёт после re-enrichment + rebuild), mono-статус
  `NOTE DELETED · MAP WILL UPDATE AFTER RE-ENRICHMENT`.
- 409 → refetch + статус `NOTE CHANGED ELSEWHERE — RELOADED`, подтверждение сбрасывается;
  404 → считать уже удалённой: refetch + статус `NOTE ALREADY DELETED`; 502 → `EDITING DISABLED`.
- Orange в этом флоу не используется (G9); подтверждение — двухшаговое, «опасный» шаг = dark filled.

**АР-7. Контраст кнопок редактора (баг «SAVE просто чёрная»).** `chromeTextClass`
(`design/theme.ts`) включает `text-ink-black`; в SAVE-кнопке `NoteEditor` он конфликтует с
`text-cream-paper`, и побеждает порядок правил в CSS, а не порядок в className (`cx` — простой
join без tailwind-merge) → чёрный текст на чёрной кнопке. Исправление:
- перевести кнопки `NoteEditor` (SAVE/CANCEL/EDIT/DELETE/CONFIRM DELETE) на существующий
  примитив `Button` из `ui/primitives.tsx` (его варианты уже решают цвет корректно) —
  не хардкодить классы заново;
- прогнать grep по всем сочетаниям `chromeTextClass` + `text-*` в className: каждое такое место —
  кандидат на тот же конфликт; исправить найденные (либо использовать примитивы, либо локальный
  класс без цветового утилити);
- регрессионный тест: у SAVE-кнопки computed-класс не содержит одновременно двух text-цветов
  (проще: тест, что SAVE использует `Button` с variant="dark").

## Инварианты спринта

- S7-1. Пайплайн кластеризации (параметры reducer/clusterer, подпись кэша, `n_noise`) не меняется;
  меняется только **вход** 2D-проектора.
- S7-2. На карте не рендерится ни один `<rect>`-халл ни в одном режиме.
- S7-3. Подписи кластеров видны только в CLUSTER-режиме; ни одна пара видимых подписей не
  пересекается (по оценочным bbox); подпись выделенного кластера видна всегда.
- S7-4. Orange по-прежнему только на активном чипе легенды (и nav) — G9. Новые цвета — только в
  `palettes.ts`, в muted-семействе.
- S7-5. Все правки токенов/палитр синхронны между `styles.css` и `theme.ts`, если затрагивают
  токены (G13); viz-палитры живут только в `palettes.ts`.
- S7-6. Существующее поведение выделения (highlight по чипам, шум в CLUSTER — серый/UNCLUSTERED)
  сохраняется; меняется только отрисовка подписей и дефолт TOPIC.
- S7-7. Удаление — только через внутренний API бота, под `journal_lock`, с обязательным
  optimistic lock (`expected_sha256`); layer3 в vault не пишет (mount остаётся `:ro`).
- S7-8. Удаление без подтверждения в UI невозможно (двухшаговый флоу).
- S7-9. Файл дня при удалении заметок не удаляется никогда (v1).
- S7-10. Чистка осиротевших строк БД выполняется только кодом бота (enrichment/reconcile), не layer3.

## Критерии приёмки

- **AC-1.** Backend-тест: при `N >= 15` фейковый projector получает векторы размерности
  фейкового reducer'а (не 1024); при `5 <= N < 15` — сырые векторы; существующие тесты
  детерминированной раскладки (N < 5) зелёные.
- **AC-2.** Frontend-тест: в CLUSTER-режиме в svg карты нет ни одного `rect`-элемента халла;
  подпись кластера расположена в медиане координат его точек (проверить на фикстуре с известными
  точками).
- **AC-3.** Тест коллизий: фикстура с двумя кластерами с почти совпадающими центроидами → видима
  одна подпись; после клика по чипу второго кластера — видима его подпись (E3, E4).
- **AC-4.** Тест режимов: в MOOD и TOPIC режимах подписи кластеров отсутствуют (S7-3).
- **AC-5.** Тест TOPIC-палитры: без выбора все точки `#858483`; с выбором — совпадающие `#181818`,
  прочие `#dedede`; E6.
- **AC-6.** Тест легенды: высота контейнера легенды идентична во всех трёх режимах (fixed height).
- **AC-7.** Тест `normalizeTimeline`: bucket без `total` → 0, NaN не появляется в модели stream (E8).
- **AC-8.** Тест гонки NotePanel: отложенный ответ первого клика не перезаписывает второй (E9).
- **AC-9.** Тест tooltip'а stream: pointermove над серединой диапазона → tooltip с корректной
  неделей и числами; pointerleave прячет (E10).
- **AC-10.** Тест месячных подписей: общая функция даёт одинаковую неделю для heatmap и stream (E12);
  stream-svg имеет `overflow-visible` (E11).
- **AC-11.** README не содержит `text-embedding-3-small`; `palettes.ts` не экспортирует
