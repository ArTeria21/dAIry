# Sprint 5 — Seasons 2.0: настоящий calendar heatmap + динамика тем

## Цель

Seasons превращается из нечитаемого грида карточек в «год с высоты птичьего полёта»:
GitHub-style mood-heatmap с реальной структурой недель и пропусками + обзор динамики тем
(stream graph топ-тем) вместо 23 несравнимых спарклайнов.

## Контекст (см. fable_report.md §1.4, P1-5, P1-7)

- Текущий «календарь» — CSS auto-fill грид карточек с датами: нет недель/месяцев, нет пустых
  клеток за дни без записей, дата конкурирует с цветом. Удаляется целиком.
- Текущие «Topics over time» — 23 спарклайна, каждый нормирован на собственный максимум
  (несравнимы), без осей и дат. Удаляются целиком.
- `/api/calendar` уже отдаёт все нужные поля дня; `/api/topics/timeline?bucket=week` отдаёт
  недельные counts по темам.
- После спринта 2 существует `ui/Legend.tsx` (переиспользуем для mood-легенды календаря) и
  правило G10 (единая mood-палитра).
- После спринта 3 существует `#journal/{date}` (ссылка READ THIS DAY в DayPanel уже есть).
- `d3` объявлен в package.json и не используется — в этом спринте начинает использоваться
  (`d3-shape` для stream graph). Если по завершении останется неиспользуемым — удалить из
  зависимостей.

## Scope

### In scope
1. Календарь-heatmap: недели × дни недели, месячные подписи, пустые клетки, mood-цвет +
   confidence-прозрачность, tooltip, клик → существующий DayPanel.
2. Mood-легенда календаря через `ui/Legend.tsx`, клик по mood — фильтр календаря.
3. Backend: `total` (число заметок недели) в `/api/topics/timeline` — для расчёта долей.
4. Stream graph топ-8 тем + OTHER по неделям (d3-shape); выбор темы ← синхронизирован с
   кросс-фильтром календаря (существующее поведение сохраняется).
5. Удаление старого грида и спарклайнов + их тестов; новые тесты.

### Out of scope
- BERTopic / темы из кластеров (следующая очередь — см. fable_report.md P1-7 «детали»).
- Аннотации пиков, drill-down по теме.
- Facts-дашборд и корреляции (P1-8, отдельный будущий спринт).
- Изменения карты и Reader.

## Ключевые архитектурные решения

**АР-1. Раскладка heatmap.** Компонент `web/frontend/src/seasons/CalendarHeatmap.tsx`, чистый SVG:
- Строки — дни недели (Пн…Вс, ISO: понедельник первый), 7 строк, слева mono-подписи `MON WED FRI`
  (через одну, как в GitHub).
- Колонки — недели. Диапазон: от понедельника недели самой ранней даты в данных до воскресенья
  недели самой поздней. Группировка дат по неделям — арифметикой дат без ручных ISO-номеров
  недель (сдвиг к понедельнику: `d - ((getDay(d)+6)%7)`); библиотеку `date-fns` не добавлять,
  достаточно нативного `Date` в UTC-полночь.
- **Годы — отдельными блоками**, самый свежий сверху; заголовок блока — mono `2026`.
- Месячные подписи — mono uppercase над колонкой недели, содержащей 1-е число месяца.
- Клетка: rect ~12×12, `rx=2`, hairline-обводка. Дата — только в tooltip (`<title>` +
  aria-label `"2026-04-11 · MIXED"`), не в клетке.
- Заливка: `moodPalette[mood]`; `fill-opacity = 0.35 + 0.65 * clamp(mood_confidence, 0, 1)`
  (низкая уверенность видна, но бледнее). День без записей — без заливки (только hairline).
  День с записями без mood (day==null, а заметки есть — данных о таких днях в `/api/calendar`
  нет, см. E4) — Fog `#eeeeee`.
- Выбранная клетка — обводка Signal Orange (единственный orange, G9).
- Клик по клетке с данными → `selectedDay` → существующий `DayPanel` (сохранить вместе с его
  ссылкой READ THIS DAY). Клик по пустой — no-op.

**АР-2. Фильтры календаря.** Два независимых приглушения (`fill-opacity → 0.15` независимо от
confidence):
- выбранный mood в легенде → дни других mood приглушаются;
- выбранная тема в stream graph → дни без этой темы приглушаются (существующая логика
  `topicsByDate` из map-payload — сохранить источник).
Активны оба → приглушение по объединению условий (день ярок, только если проходит оба фильтра).

**АР-3. Backend: доли тем.** `/api/topics/timeline` в каждом bucket дополняется полем
`total` — число заметок этой недели (не сумма counts: у заметки несколько тем). Реализация — тем
же группирующим проходом по notes, что строит counts. Существующая структура ответа сохраняется
(аддитивное изменение).

**АР-4. Stream graph.** Компонент `web/frontend/src/seasons/TopicsStream.tsx`:
- Данные: недельные buckets; топ-8 тем по суммарному count за весь период, остальные суммируются
  в `OTHER`. Тема `reflection` **исключается из топ-8** (тема-по-умолчанию, забивает сигнал — см.
  fable_report.md, приложение) и попадает в OTHER; константа `EXCLUDED_FROM_TOP = ["reflection"]`
  с комментарием.
- Значение ряда — **доля**: `count / max(total, 1)` (устойчивость к неровной частоте записей).
- `d3-shape`: `stack().offset(stackOffsetWiggle).order(stackOrderInsideOut)` + `area()` с
  `curveBasis`. Только `d3-shape` (точечный импорт), не весь d3.
- Цвета слоёв — `clusterPalette` из спринта 2 (8 muted-цветов, по одному на тему), OTHER —
  Mortar `#dedede`. Выбранная тема — слой с обводкой ink; остальные при выборе приглушаются
  opacity. Никакого orange внутри графика (orange — на активном чипе легенды).
- Ось X — mono-подписи месяцев по нижнему краю (те же правила, что у heatmap). Ось Y не нужна
  (wiggle-offset безосевой), подпись `SHARE OF WEEKLY NOTES` mono-caption.
- Легенда тем — тот же `ui/Legend.tsx` (chip = тема + total count; OTHER — некликабельный);
  клик — выбор/сброс темы (синхронизировано с кросс-фильтром календаря).
- Hover слоя → tooltip `TOPIC · WEEK OF 2026-04-06 · 5 NOTES (23%)`.

**АР-5. Структура страницы Seasons** (сверху вниз): заголовок → mood-легенда → heatmap (годовые
блоки) → `DayPanel` остаётся правой колонкой на десктопе → секция `TOPICS OVER TIME` со stream
graph + легендой тем. Старые `DayCell`-грид и `TopicSparkline` удаляются вместе с их тестами.

## Инварианты спринта

- S5-1. Mood-цвета клеток идентичны `moodPalette` карты (G10); никаких новых mood-цветов.
- S5-2. Пустые дни рендерятся (сетка непрерывна по календарю); «пропуск» визуально отличим от
  «был день с записью».
- S5-3. На странице по-прежнему нет raw-текста и путей файлов (существующий no-leak тест
  адаптировать, не удалять).
- S5-4. Год данных помещается по ширине без горизонтального скролла при ширине контента 1200px
  (52 недели × ~14px ≈ 730px — укладывается; проверить расчётом в тесте размеров не нужно,
  достаточно фиксированной ширины клетки ≤ 14px с gap ≤ 3px).
- S5-5. `d3-shape` — единственный используемый d3-модуль; если в итоге не используется — `d3`
  удаляется из package.json.
- S5-6. Highlight-состояния: одновременно не более одного выбранного mood и одной выбранной темы;
  на странице не более двух orange-элементов нет — **уточнение G9 для этого view**: orange несут
  только активные чипы легенд (максимум два: mood-чип и тема-чип) и обводка выбранного дня.
  Если формальная трактовка G9 («один активный элемент») конфликтует — приоритет у этой спеки,
  зафиксировать решение в worklog.

## Edge cases и ожидаемое поведение

| # | Кейс | Ожидаемое поведение |
|---|---|---|
| E1 | Данные в двух календарных годах | Два годовых блока, свежий сверху |
| E2 | Первая неделя года начинается в прошлом году (1 янв = четверг) | Клетки «хвоста» декабря в блоке нового года рендерятся пустыми и некликабельными (принадлежат другому блоку) — сетка каждого блока начинается с недели, содержащей 1 января |
| E3 | `mood_confidence` = null | Прозрачность как при 0.5 |
| E4 | День в `/api/calendar` с `mood=null` | Заливка Fog, tooltip `NO MOOD` |
| E5 | Выбраны и mood, и тема одновременно | Ярки только дни, проходящие оба фильтра; сброс независимый |
| E6 | Bucket с `total=0` (данных нет — не должен приходить, но) | Доли считаются как 0, деления на ноль нет |
| E7 | Меньше 8 тем в данных | Топ-N по факту, OTHER может отсутствовать |
| E8 | Одна-единственная неделя данных | Stream graph вырождается — рендерить без ошибок (area из одной точки допустимо не рисовать, показать `NOT ENOUGH DATA` при < 3 buckets) |
| E9 | Пустые ответы обоих API | Существующие empty-состояния (`NO DAYS TO SHOW` / `NO TOPIC SIGNAL`) сохраняются |
| E10 | День есть в календаре, отсутствует в `topicsByDate` | При тематическом фильтре считается «не содержащим тему» → приглушается |
| E11 | Високосный год / разная длина месяцев | Подписи месяцев корректны (по неделе, содержащей 1-е число) |

## Критерии приёмки

- **AC-1.** Юнит-тесты раскладки (чистые функции, вынесенные из компонента): группировка дат по
  неделям с понедельника; позиция месячных подписей; годовые блоки (E1, E2, E11).
- **AC-2.** Компонентный тест heatmap: дни без записей — пустые клетки; mood-дни — правильный
  цвет из `moodPalette`; confidence влияет на opacity (E3); клик открывает DayPanel с summary и
  ссылкой READ THIS DAY.
- **AC-3.** Тест фильтров: выбор mood в легенде приглушает прочие дни; выбор темы — дни без темы;
  комбинация — E5.
- **AC-4.** Backend-тест: `total` в каждом bucket = числу заметок недели (не сумме counts).
- **AC-5.** Компонентный тест stream graph: топ-8 без `reflection`, OTHER агрегирует остальное;
  выбор темы синхронно подсвечивает слой и фильтрует календарь; < 3 buckets → NOT ENOUGH DATA (E8).
- **AC-6.** Старые `DayCell`-грид и `TopicSparkline` удалены из кода и тестов; no-leak тест
  страницы зелёный (S5-3).
- **AC-7.** Все команды проверки зелёные.
